# Open Research Questions

Prioritize questions whose answers could materially change future agent behavior.

## Resolved / narrowed this cycle
The broad question “Which context artifacts most improve visual quality in AI-generated frontend work?” now has a useful first answer for Claude: a brief-grounded design contract plus visual references/rendered inspection and explicit evaluation criteria are supported by Anthropic's current workflow evidence. Remaining comparative questions belong below.

**Storybook MCP investigation (2026-10-09):** Official Storybook MCP offers component-manifest lookups and optional story/test tools, not independent design judgment. Documentation tools depend on framework-generated manifests; automated tests require configured addons. Storybook AI remains preview. Issue #36364 reports a GET/SSE hang in 10.6.0; check the installed transport rather than assuming every MCP client fails. The comparison against reading source/stories directly remains untested. Sources: https://storybook.js.org/docs/ai/mcp/overview/ and https://github.com/storybookjs/storybook/issues/36364 .

## New focused test — 2026-10-13

- Compare optimistic updates, pending-only feedback and durable offline queues on matched tasks. Seed concurrent writes, timeout-after-commit, server rejection, filtered-row disappearance and refresh while offline. Measure incorrect beliefs that changes were saved, lost work, duplicate effects, recovery time, task completion and assistive-technology status comprehension. ## Current queue
- **Numeric-input falsification (2026-10-24):** Compare `type=number`, `type=text inputmode=decimal` plus reviewed locale parser, and React Aria NumberField in matched quantity, monetary and numeric-identifier tasks. Seed en-US/de-DE ambiguous separators, Arabic-Indic digits, negative decimals on mobile, step snapping, rerender during editing, Enter vs blur, scroll/stepper accidents, leading zeros, precision overflow, server round-trip and clean controls. Measure silent value mutation, accepted wrong values, accessibility and completion. GOV.UK revised decimal/minus guidance in June 2026; React Aria #9059 is an open version-specific negative-value report, not a general defect.

- **Mobile bottom-sheet falsification (2026-10-18):** Compare a bottom-styled native `<dialog>`, maintained Base UI Drawer v1.9.0 and existing Vaul on matched iOS Safari/Home Screen PWA + Android tasks. Seed nested scroller/combobox, software keyboard, backdrop/Escape/Back/swipe with unsaved form, and correct non-gesture controls. Measure data loss, focus return, body scroll bleed, keyboard visibility, accidental dismissals and unnecessary drawer conversions. Vaul declares itself unmaintained (https://github.com/emilkowalski/vaul); Base UI v1.9.0 documents keyboard/swipe fixes (https://base-ui.com/react/overview/releases) but needs device verification. Do not infer reliability from popularity or docs alone.
- Figma Code Connect v2 (2026-10-18): test no mapping vs simple source mapping vs reviewed `.figma.ts` templates for component/prop/slot accuracy and rendered fidelity. The official skill's read-back check does not run `figma connect preview` or verify Dev Mode. CLI v2.0.2 describes limited Professional-plan publishing while the skill still says Organization/Enterprise; confirm actual seat/tool entitlement before recommending. Sources: https://github.com/figma/code-connect/blob/main/CHANGELOG.md ; https://github.com/figma/mcp-server-guide/blob/main/skills/figma-code-connect/SKILL.md .
- Passkey migration (2026-10-13): compare conditional autofill alone versus autofill plus explicit cross-device passkey entry and recovery. Include passkey absent locally, phone QR, cancellation, revoked credentials, loss of devices, screen reader/keyboard and password-manager failures; measure first-try success, lockout, account-switch mistakes and downgrade/abuse risk. Official journey guidance: https://developers.google.com/identity/passkeys/ux/user-journeys ; observational inconsistency across 111 sites: https://www.usenix.org/conference/soups2025/presentation/ramat-poster .
- When do one-question-per-page, grouped expert forms, linear step indicators and resumable task lists outperform one another? Compare novice public-service and expert back-office users with fixed and branching tasks; measure total effort, errors, Back/resume fidelity, screen-reader orientation and misleading progress counts. Sources: GOV.UK question pages/task lists, BOPS multiple-questions exception, USWDS step indicator, NHS question pages (reviewed 2026-10-13).
- Does Google Stitch's code-to-design → DESIGN.md → React workflow improve rendered fidelity over a local preview plus direct source inspection? In paired Claude/Codex trials, verify remote edits persist (open upstream issue #68), audit actual source sent to the service, measure component reuse, responsive/keyboard defects and correction cost. Source inspection (2026-10-12) found that its React validator checks only a Props interface and hex literals; its style pack also imposes blanket perpetual motion and typography bans. Treat these as unvalidated heuristics, not accessibility or design certification. Source: https://github.com/google-labs-code/stitch-skills ; https://github.com/google-labs-code/stitch-skills/issues/68 .
- Does Storybook MCP improve reuse of documented components beyond reading source and stories directly? Run matched Claude/Codex trials with valid and invented props, stale/missing manifests, component-state tests and clean controls. Compare contract errors, accessibility regressions, context cost and time; separate MCP activation from causal improvement. Check the open 10.6.0 SSE transport issue (#36364) against the exact installed release.
- In autonomous browser-based UI reviews, which controls prevent unintended cross-origin requests or state-changing behavior? Compare Playwright MCP origin filters (documented as non-boundaries), Chrome DevTools MCP URL filters (Chrome-version and attachment constraints), and agent-browser opt-in domain/action policies. Use benign redirect, subresource, WebSocket, file, WebMCP, and state-changing-button fixtures; separate browser guardrails, host isolation, visible-UI coverage, and actual blocked actions.
- Does Microsoft's Playwright CLI skill improve visual-QA defect detection beyond CLI without the skill or Playwright MCP? Compare seeded defects and clean controls, inspected screenshots versus semantic snapshots, real UI journeys versus page-provided WebMCP shortcuts, accessibility/focus regressions, and context cost. Separate successful browser automation from verified visual quality; treat vendor efficiency claims as unvalidated.
- Accessibility skill trial (2026-10-13): compare no-skill Playwright+axe against 84EM's lightweight WCAG checklist and selected Zivtech planner/critic/test skills in matched Claude/Codex BUG/CLEAN fixtures. Test modal focus return, combobox arrows, OTP paste, live announcements, misleading alt, zoom, and clean controls; measure correct repairs, false-positive edits, AT-adjudicated defects, time and context cost. Zivtech's own evaluation discloses fixture leaks and weak clean-case acceptance (6/55 vs 2/55 in a probe); do not infer causal uplift from fixture counts. Sources: https://github.com/zivtech/accessibility-skills/blob/main/docs/evaluation.md ; https://github.com/84emllc/claude-wcag-skill ; https://playwright.dev/docs/accessibility-testing .
