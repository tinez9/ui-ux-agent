# Design Playbook for AI Coding Agents

## 1. Establish context
Identify product type, primary user, primary task, product goal, content density, target devices, brand constraints, technical constraints, and accessibility requirements.

## 2. Define an explicit visual thesis
Use concrete language such as:
- editorial, restrained, high-contrast, image-led
- technical, dense, calm, data-forward
- cinematic, dark, spacious, content-first
- playful, tactile, bright, motion-led

Avoid vague directions such as “modern”, “clean”, or “premium” unless translated into concrete rules.

## 3. Design hierarchy and flows first
Establish page hierarchy, primary action, secondary actions, navigation, information grouping, content order, key states, and responsive priorities before polishing surfaces.

## 4. Choose patterns intentionally
For each major interaction ask what problem is solved, which conventional pattern already works, whether novelty adds value, what happens on mobile, how keyboard/touch behave, and what loading/empty/error/success states exist.

## 5. Add differentiation selectively
Explore richer previews, contextual actions, intelligent filtering, comparison, progressive exploration, command interfaces, direct manipulation, personalization, and AI-assisted workflows only where they improve the product.

## 6. Define a compact system
Specify typography roles, spacing scale, semantic colors, shapes, borders/elevation, motion rules, icon style, layout constraints, and component-state behavior.

## 7. Implement one representative slice
Build one high-information page or workflow before scaling the system.

## 8. Inspect rendered output
Use screenshots/browser inspection. Look for weak hierarchy, accidental symmetry, repetitive cards, poor density, inconsistent alignment, generic component-library appearance, bad mobile recomposition, and visual noise.

## 9. Test states
Verify hover, focus, active, disabled, loading, empty, error, success, reduced motion, keyboard navigation, touch targets, and responsive transitions.

## 10. Refine with evidence
Identify whether a change is motivated by user task, UX principle, accessibility, performance, visual coherence, brand, product differentiation, observed trend, or stakeholder preference. Do not present subjective taste as objective UX evidence.
